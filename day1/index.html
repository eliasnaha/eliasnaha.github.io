◆ Build log · Day 01 · Infinite environment generation

A text command becomes a world you can verify

An agent harness that turns a plain-language command into a small 2D physics scene — then proves the scene is sound entirely in code, reading the engine's own state instead of looking at a single rendered pixel.

statustwo rounds in one day tests150 passing enginepymunk 2D verifiercode-only, no VLM

The loop is simple to state and hard to get right: a command comes in, an environment goes out, and a verifier decides whether that environment is fit to train on. Because the world is simulated in 2D, its truth is fully available through code — every position, velocity, angle and contact — so the verifier never needs a vision model guessing at frames.

These are the first three demos. Each one is driven by the real harness (python -m harness play), and each one changed how the verifier thinks. The command is shown above every clip; the machine's world plays below it.

Two voices on this page: monospace is the machine — commands, state, verdicts — and sans is us, narrating what it taught us.

Round one · scenes on a fixed toolkit

>push the ball into the zone

Verifier impact

Getting this scene to pass taught L0 that a goal-zone sensor overlapping the floor is not a collision, and taught L1 that objects must rest exactly on the ground surface y = 1 — spawn one a few pixels high and the settling check rightly flags it as unstable.

02 climb_platforms pass
>climb the platforms to the zone
result reached goal steps 222 policy greedy · no LLM
Verifier impact

Building a staircase the agent could actually climb exposed the gap between coherent and solvable: a scene can pass every physical check and still be unwinnable. That gap is exactly what the next layer — L3, solvability — is being built to close.

03 broken_floating reject
>a box floating in mid-air with no support
rejected at L1 · no_displacement drift 429 px class ENV_ERROR
Verifier impact

Our canonical negative fixture. The box has no support, collapses under gravity, and L1's settling rollout catches the 429 px drift — proof that the verifier judges what the world does, not what the code that built it claims.

How a round-one scene is checked

funnel · stops at first failure
L0 · static

Does it build?

Sandbox-clean, agent present, nothing out of bounds, no initial interpenetration.

L1 · settling

Does it hold?

Run it under gravity with no input; reject NaNs, drift, and objects that never rest.

L2 · goal

Is the goal real?

Success must be a pure predicate that isn't already true before the agent does anything.

Round two · the machine designs its own games

one prompt → one original game → verified → witness replay

Same day, second rung: the harness got out of the game-design business. No more worked example, no genre — the model writes the whole game from one prompt (entities, its own action set, its rules, win/lose) plus 1–6 milestone predicates decomposing its own rules. Universal oracles it can't redefine check sanity, honesty (doing nothing never wins, every action must measurably do something), and solvability: a seeded random search must actually win — its winning sequence, the witness, is what plays below. Five failed attempts were caught and repaired through the machine report alone.

04 retro_burn_lander pass
>a lunar lander: touch down gently on the pad — too fast, or the rocks, destroys the ship
attempts 2 witness 68 ticks milestones 5/5
What the verifier caught

Attempt 1 rejected: coast was a dead action — measured world-effect exactly 0.0. The repair made every action live. The game's own twist: free-fall is always lethal, so winning demands timed retro burns.

05 wrecking_ball_yard pass
>a wrecking ball on a chain: swing it to knock the crate tower off its ledge
attempts 2 witness 68 ticks milestones 4/4
What the verifier caught

Attempt 1 unsolvable — diagnosis: stuck between swing_started and reached_crates, with lopsided action efficacy (80 vs 206): the ledge itself blocked the swing path. One geometry fix, then a pendulum you pump into resonance — no single action wins.

06 volcano_hopper pass
>volcano hopper: climb the stone slabs before the rising lava catches you
attempts 4 witness 84 ticks milestones 3/3
What the verifier caught

Three rejections: a dead wait action, then twice stuck between the first and second slab. The diagnosis localized the broken hop; the fix was a redesign — a diamond with two winning paths and a lava clock that makes hesitation fatal.

* amber flashes in the round-two clips are milestones latching in real time — the game's own checkpoints, recorded by the harness the first time each becomes true. They double as the dense, code-defined progress signal a reward model could train on.

How a generated game is checked

universal oracles · the game can't redefine them
G0 · static

Does it build?

Sandbox-clean, required symbols, exactly one controlled body, nothing overlapping or out of bounds.

G1 · rollout

Is it sane & honest?

No NaNs or escapes; deterministic; doing nothing never wins; every declared action measurably does something.

G2 · goal

Are goal & milestones real?

Pure predicates, false at t=0; 1–6 ordered milestones that decompose the game's own rules.

G3 · solvability

Can it be won?

Seeded random search must win it; milestones guide a second pass and pinpoint where a failing game is stuck.
